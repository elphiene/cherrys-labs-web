tidal-collaborative

overview

A self-hosted server that lets multiple users collaboratively sync Tidal playlists in real time. Sign in with your Tidal account in any browser, link a playlist, and every change — adds, removes — propagates to all collaborators automatically.

Status: work in progress. Self-hosted via Docker, home lab friendly. Requires a free Tidal developer app registration for OAuth.

how it works

The server polls each linked Tidal playlist every 60 seconds. It detects added and removed tracks via set-difference, writes changes to SQLite, then calls the Tidal API to propagate those changes to every other linked user's playlist. All open browser tabs receive a WebSocket notification instantly.

Authentication uses OAuth 2.1 PKCE entirely server-side — no token ever touches the browser. Tidal access and refresh tokens are encrypted at rest with AES-256-GCM. Sessions use httpOnly cookies with a 30-day expiry.

tech stack

Server: Node.js 20 LTS, Express 4, ws (WebSocket), better-sqlite3, express-session, Node.js built-in crypto (AES-256-GCM).

Database: SQLite — the entire state is one file, trivial to back up.

Container: Docker on node:20-alpine. Multi-platform build — amd64 and arm64. Published to Docker Hub.

Frontend: Vanilla HTML / CSS / JS. No frameworks.

Tidal API: openapi.tidal.com/v2 (JSON:API).

setup

Pull and run with Docker Compose — no build needed:

curl -O https://raw.githubusercontent.com/elphiene/tidal-collaborative/main/docker/docker-compose.yml
docker compose up -d

Then open http://localhost:3000 — the setup wizard handles the rest, including Tidal OAuth configuration and encryption key generation.

System requirements: Linux, Docker Engine 24+, ≥128 MB RAM, any modern browser. Users must be on the home LAN or connected via VPN.

development

Roadmap: track reorder sync, granular permissions (view-only collaborators), configurable poll interval per playlist, pagination for very large playlists (>500 tracks).
